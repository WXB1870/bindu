# 架构与文档审查：2026-09-16

## 结论与范围

总体分层、硬件抽象、任务/策略/执行分离和灵巧手方向合理；现有资料不足以证明任何实现“最优”。主要问题是：完整平台设计与首期必要实现混排、若干执行边界未闭合、同一规则多处维护。本轮已修正文档，不代表代码缺陷已通过测试修复。

检查范围：`bindu/` 现有 13 份 Markdown、总体图片的既有生成记录，抽查根目录 Galbot/YDH/control 来源；核对关键控制器和平台官方资料。没有用户 MoveIt 源码、SDK 或真机访问证据，因此未做代码、硬件或全包兼容测试；没有重新生成图片。不是对全部外链可用性的全面扫描。

## 1. 主要发现与处理

“高”表示照原文字实现可能影响动作/状态正确性；“中”主要影响实现选择与维护成本。表中原文定位指本轮修订前版本，链接指修正后的主文档。

| 编号 / 优先级 | 发现与依据 | 影响及本次处理 |
|---|---|---|
| R01 高 | 执行契约第 6 节对缓冲余量统一使用制动条件，没有区分正常最后一段 | 有限轨迹接近终点也可能被提前截断。增加显式结束标记、终端状态/容差和按模式区分的结束/断流规则 |
| R02 高 | 架构 7.3 允许按跟踪状态“调整推进速度”，同时要求唯一已提交时间轴；下层权限不明确 | 暗中变速会使 VLA 的旧前缀/切换时间失效。改为执行端提交新 revision 和生效边界，采样器只采已批准曲线；预授权停止单独处理 |
| R03 高 | 持物会话接管“灵巧手及必要保持资源”，未具体说明臂后续如何运动 | 可能永久锁臂或产生第二写入者。拆开持物责任与臂写权限，明确受控运动/确认移交；手部保持继续 |
| R04 高 | 停止设计重视速度/加速度/jerk，却未明确停止路径包络 | 平滑制动仍可能碰撞或破坏接触。补充制动距离/SDK 前缀、几何包络与阶段约束；不承诺所有故障可平滑停止 |
| R05 中 | 计划表将 ros2_control、JTC、Ruckig 并列为执行基线，正文又允许 SDK 适配 | 实现者可能串联多个插值器。改为硬件能力分支选择一个实际后端，MoveIt 使用标准轨迹入口；未来段拼接另验收 |
| R06 中 | 计划 4.2 写“持物未确认不抬升/运输”，同时又要求抬升验证持物 | 容易形成循环判据。明确初步抓取证据→受限试抬→确认保持→运输；阈值待设备/场景确定 |
| R07 中 | 完整对象/会话、十三包布局、行为树、A0–A4/P0–P6 同时出现 | 首条实现链的前置条件容易膨胀。改为三类自研职责、固定资源表和显式状态机；A 活动并入 P0；RTC/复杂并发按需增加 |
| R08 中 | 上下文收录图示变更；进度重复每轮设计历史；架构、计划、图示反复定义执行语义 | 多处同步易遗漏。明确各类信息主文档，压缩上下文/进度，图示保留但改为辅助；历史过程只追加 |
| R09 中 | 持物/场景版本规则没有说明只校验相关依赖 | 无关对象每帧更新可能令候选不断失效。增加依赖范围；相关环境失效仍需停止/重规划，不能为减少拒绝而忽略障碍 |
| R10 中 | Humble 基线正确但长期迁移窗口不突出；Orin 只给系列名；Voxel 外链已失效 | 增加支持期、构建/运行资源区别及锁版要求；修复已发现 404，当前 Nav2 页面只作概念引用，不跨版本复制参数 |

## 2. 官方资料核对结果

- MoveIt 支持对接自有轨迹 Action，ros2_control 非强制依赖；页面部分调试示例保留 ROS 2 更新 TODO，不能直接当部署脚本。[Humble 控制接口](https://moveit.picknik.ai/humble/doc/examples/controller_configuration/controller_configuration_tutorial.html)
- Humble JTC 按位置/速度/加速度字段采用不同插值；页面指出替换会丢弃旧轨迹。不能据此声称满足我们要求的锁定前缀与动作块衔接，仍需锁定安装版本测试。[JTC 文档](https://control.ros.org/humble/doc/ros2_controllers/joint_trajectory_controller/doc/trajectory.html)
- Ruckig Tracking 为 Pro，Community 中间点走云端；位置上下界参数亦标为 Pro。社区版状态到状态生成可评估，但路径/位置范围检查不能省略。[官方 README](https://github.com/pantor/ruckig)
- Humble Servo 的局部命令路径与现有建议相符；KDL 插件限串联链，不能把整只耦合灵巧手自动视为同一个串联 IK 组。[Servo](https://moveit.picknik.ai/humble/doc/examples/realtime_servo/realtime_servo_tutorial.html)、[运动学配置](https://moveit.picknik.ai/humble/doc/examples/kinematics_configuration/kinematics_configuration_tutorial.html)
- Humble 对 Ubuntu 22.04/arm64 的对应关系成立，支持到 2027 年 5 月；截至本轮审查不足一年，应在锁版时安排升级评估。[REP 2000 官方源码](https://raw.githubusercontent.com/ros-infrastructure/rep/master/rep-2000.rst)
- Isaac ROS 3.2 对应 JetPack 6.1/6.2；FoundationPose 构建模型引擎需至少 7.5 GB 空闲 GPU 内存。后者不是推理运行内存，不能拿来证明任意 Orin 足够或不足。[平台](https://nvidia-isaac-ros.github.io/v/release-3.2/repositories_and_packages/isaac_ros_common/index.html)、[FoundationPose](https://nvidia-isaac-ros.github.io/v/release-3.2/repositories_and_packages/isaac_ros_pose_estimation/isaac_ros_foundationpose/index.html)
- Nav2 旧路径访问失败，现行 Voxel 说明明确三维观测投影为二维代价图；这不等于全身三维避碰。现行页面分支不同，仅核对概念。[Voxel](https://docs.nav2.org/rolling/configuration_and_development/configuration_guide/core_servers/costmap_2d/costmap_plugins/voxel/)、[odom/TF](https://docs.nav2.org/jazzy/configuration_and_development/first_time_robot_setup_guide/odom/setup_odom_gz/)

其余 ASR/YOLO/数据工具保留此前候选身份，本轮未重做全版本、许可证或性能审查。文档有引用不等于目标硬件验证。

## 3. 当前更合适的实现取舍

“更合适”依据是减少重复开发、缩短首个物理闭环路径、保留可验证替换边界；这是工程建议，不是基准测试结论。

1. 优先查清 SDK 实际支持什么，再从架构 7.2 分支选后端。已有轨迹/保持能力可复用；只有位置写入时再补缺失的周期执行。
2. 保留统一执行入口、真实反馈、停止/保持、时间与动作来源，这些不能因简化而删除。首期资源固定、本地管理即可。
3. 固定任务先用显式状态机；算法复用 MoveIt/Nav2 等现有候选，灵巧手先验证一个可复现抓型。硬件配置决定能否增加连续 IK、复杂抓型或模型策略。
4. 数据和 VLA 骨架早建，模型接管在执行/数据链验证之后；不把 VLA 移出一期，也不以训练模型掩盖接口问题。
5. 下一份有价值的证据是具名命令/反馈样例和能力表，然后是模拟后端故障用例；继续增加总体图不能替代这些交付。

## 4. 冗余的处理原则

真正冗余的是相同规范的多份正文，而不是不同粒度的图。保留用户要求的图片、总体图、七类职责展开图；删除其中重复接口表/长篇规则，链接到主定义。保留 Galbot 来源、历史决策和逐日过程，不通过删除历史掩盖建议变化。

当前信息归属见 [README](../README.md)。旧记录的版本名表示当时状态，链接通常指向现行文档，不是不可变版本快照；不能用历史标题推断当前内容仍是 v0.1/v0.2。

本轮检查本地链接、围栏、图节点引用、当前版本引用和前后文本规模；不是 Mermaid 渲染验证或运行测试。所有本轮技术修正均需在模拟/真实执行中验收，特别是正常终点、重定时、取消晚到、停止包络和持物资源移交。
